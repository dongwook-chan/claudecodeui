# Repository guidance

## Backend code

For every task that creates, modifies, refactors, or reviews backend code under `server/`, load and follow `$backend-module-standards` from `.agents/skills/backend-module-standards/SKILL.md`. Apply it only to backend code; do not impose those architecture rules on the frontend.

## CloudCLI release patches

Before updating or deploying a CloudCLI release candidate, read `/home/ubuntu/cloudcli-maintenance/patches/README.md` and `manifest.json`. Resolve `reviewItems`, apply active patches with `prepare-release.mjs`, and run the listed tests; a passing manifest check alone is insufficient.

## CloudCLI release workspace cleanup

- Before creating a candidate, inventory existing candidates for the target release and inspect their branch, patch state, uncommitted changes, and active users. Continue a compatible existing candidate when safe. Create another only for a concrete isolation need, such as a different patch set or an independent comparison, and record why; do not blindly rerun preparation after a conflict or interruption.
- Install dependencies only in candidates that need testing or building. Avoid retaining separate `node_modules` trees for abandoned attempts and completed comparisons.
- After deployment status reports success, verify health, the required browser check, and interrupted-session continuation before treating deployment work as complete. Then inspect and clean obsolete candidate worktrees and temporary patch-source worktrees, including their dependencies and build outputs. Report what was removed, what was retained and why, and disk space reclaimed. If cleanup cannot be completed, report the remaining work explicitly.
- Before removal, verify that no active process, session, deployment, operational symlink, or recovery path depends on the workspace. Protect the running release, the last-successful release, and the previous known-good release needed for rollback. Never stop the service or remove live dependencies to reclaim space.
- Preserve uncommitted or untracked work and ensure unique commits, required patch-source commits, and manifest references remain reachable through retained Git refs before removing a worktree. Do not force-remove a dirty worktree or abort an in-progress cherry-pick merely for cleanup. Use Git worktree removal for registered worktrees rather than deleting their directories directly.
- Treat ignored build/dependency directories, untracked root `node_modules` symlinks, and Husky internal `.husky/_/` files as generated artifacts. An idle managed test workspace pointing to another test workspace's packages is not a production dependency. Use the cleanup helper to detach such package links and remove obsolete clean worktrees; report that packages need reinstalling if the referring test workspace is reused. Preserve its source changes. Active/locked workspaces, production/recovery paths, external references, and tracked source links still protect their dependencies transitively. Do not retain gigabytes solely because an idle test dependency link or generated Husky files exist.
- The maintenance scripts reuse compatible candidates and automatically clean eligible worktrees after verified deployment. Use `cloudcli-deploy/scripts/deploy.sh cleanup-workspaces` to preview and add `--apply` to perform cleanup after an already verified deployment. `--retire /absolute/workspace/path` marks an explicitly completed workspace, waives its age grace period, pins detached commits in Git, and permits small ignored files to be privately archived and byte-verified before removal. Ordinary cleanup also archives idle test databases instead of retaining their large package trees. Archives are limited to 64 MiB per worktree and stored under `~/.local/state/cloudcli-deploy/workspace-archives/`; source changes and live dependencies remain protected.
- Keep failed or interrupted attempts only while they support active investigation or recovery, with a recorded reason. Revisit them on the next release task. Report removed workspaces, detached test dependency links, retained workspaces with exact reasons, and actual disk space reclaimed.
